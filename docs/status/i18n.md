# 中英双语界面 (interface language)

State: **done, validated by Leon 2026-10-17 18:52Z** (PR #58, v2026.10.17.5) · thread「中英文双语支持分析」 · decision `docs/decisions/2026-10-17-i18n-chinese-as-key.md`

What shipped:
1. Base: `web/src/i18n`, 设置 → 外观 → 界面语言, build-time check (`npm run i18n`, part of `npm run build`),
   E2E `web/e2e/i18n.spec.ts`.
2. Every web screen migrated; English in `web/src/i18n/en.ts` + `web/src/features/<f>/en.ts`.
3. Backend (`lacuna_app/i18n.py`, `i18n_en.py`, middleware in `routes/i18n.py`, cookie `lacuna_lang`):
   errors, labels, job stages, history labels (stored Chinese, shown via `episode.history_label`);
   AI edit reasons / chat replies / notes in the interface language (`in_reply_language`); voice input
   uses SenseVoice `auto` under English. Checker `tests/test_i18n.py`; API test `tests/app/test_i18n_api.py`.

Stays Chinese on purpose: transcripts, show notes, publish pack, poster brief, music credits, prompts' content
(lines marked `# i18n-ignore`). Data written earlier keeps the language it was written in.

Adding a string: write Chinese in `t()` / `tr()`, add the English
to the nearest `en.ts` / `i18n_en.py`; the checks fail the build otherwise.

Not in scope: English-language episodes (ASR, features, editing rules, publishing platform; see the analysis).
