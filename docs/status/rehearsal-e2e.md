# 端到端测试预演（2026-10-17）

在云端用一集合成的 **两小时** 两轨录音，把 Leon 真测要走的整条链路自动跑了一遍。

## 怎么跑的
- 素材：sherpa-onnx 自带的中文语音片段拼成两人对话（轮流说话、停顿 0.1–4 s、偶尔长空白、插话和抢话），44.1 kHz 16-bit 单声道，和 EP001 的 Riverside 分轨同格式，每轨 120 分钟、635 MB。
- 真跑的：导入（真 ASR：Paraformer + SenseVoice）、特征分析、生成审阅、试听流、审阅/恢复/撤销/重做、配乐（素材库上传 + 片头/间奏/片尾）、母带导出 WAV + MP3、海报渲染、上传喜马拉雅页、封面下载。
- **没真跑 Claude**（云端没有 key）：AI 第一刀、AI 对话、发布资料、海报设计都用脚本假装的 Claude 回答，所以 AI 剪得好不好、花多少钱这次没测；只测了流程、数据量和衔接。
- 工具在仓库 `scripts/rehearsal/`（生成素材、假 Claude 服务器、按顺序驱动每一步并计时），以后可以再跑。

## 结果（云端 4 核，Leon 电脑 6 核会快一些）
| 步骤 | 结果 |
|---|---|
| 导入总耗时 | 16.5 分钟（ASR 每轨约 7.7 分钟） |
| AI 第一刀（假） | 12 段，654 个操作 → 591 个改动，302 个待审（63 个无效操作被正确丢掉） |
| 审阅、恢复、撤销、AI 对话提案、批准 | 每次 < 1 秒；剧集数据 0.3 MB |
| 试听跳到任意位置 | < 0.1 秒 |
| 配乐 | 片头 / 1:00:00 间奏 / 片尾都放对位置，成品混音可跳播 |
| 导出（约 98 分钟成品，含配乐） | 约 8.5 分钟；-16.05 LUFS / -1.3 dBTP；WAV 1.56 GB，MP3 94 MB；内存约 0.8 GB |
| 发布资料、海报、上传页 | 都通过；选好封面后上传页显示「全部就绪」 |
| 其他格式导入 | m4a、mp3、flac、48 kHz、24-bit 立体声、32-bit float、两轨采样率不同：都能导入和导出 |

## 发现并修好的（PR #53，已 merge，等统一更新）
1. **两轨长短不一时，长的那条尾巴被剪掉。** 原来整集按短的那条截断，比如 Pei 先停录，Leon 最后说的话会悄悄丢掉。现在每条轨保留自己的长度。
2. **两小时一集分析停顿那步内存冲到 3.8 GB。** 原因是一次性建了很大的索引表；改成分块，结果完全一样，峰值降到 ASR 解码时的水平（约 2 GB）。EP001 那样 73 分钟的不会出问题，2 小时以上才明显。

## Leon 真测时要注意
- **喜马拉雅文件大小**：两小时一集导出的 WAV 约 1.5–1.9 GB。我查不到喜马拉雅网页上传的确切大小上限；如果 WAV 传不上去，改传同一文件夹里的 MP3（约 100 MB，响度一样）。
- 导入一集两小时的大约需要 15 分钟左右（在你电脑上可能更快），这段时间可以关掉页面，回来点「继续」也不会重做已完成的步骤。
- AI 第一刀按 EP001 推算，两小时一集约 $3、10 多分钟。
- 上传页里「选封面」后要等 1 秒左右才显示就绪，属正常。
